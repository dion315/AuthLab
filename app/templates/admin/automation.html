Why this exists

The console is the right interface for the first hour with a new provider and the wrong one afterwards. These endpoints let a pipeline export the activity log as evidence, push a known connection definition before a test, and check a provider's configuration without a browser.

Endpoints

MethodPathScopeWhat it does
GET/api/admin/eventsevents:read Activity log as JSON or CSV. ?format=csv&kind=login_failure&since_minutes=60
GET/api/admin/sessionssessions:read Live sessions and their claims.
GET/api/admin/connectionsconnections:read Export every connection. Secrets are never included.
POST/api/admin/connectionsconnections:write Create or update from exported definitions.
POST/api/admin/connections/{slug}/testconnections:read Run the discovery/metadata check. Branch on ok, not the status code.

Example

curl -H "Authorization: Bearer $AUTHLAB_TOKEN" \
  "{{ api_base_url }}/api/admin/events?format=csv&kind=login_failure&since_minutes=1440" \
  -o evidence.csv

An administrator session cookie is accepted anywhere a token is, which is what lets the download links below work without a separate credential.

Import a connection

Paste a definition exported from another instance. Matching is by slug: an existing connection is updated rather than duplicated.

Client secrets and SAML private keys are never exported, so re-enter them on the connection afterwards. An import leaves an existing secret untouched.
