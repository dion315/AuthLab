The other half of OAuth

Every other page here tests the client side: a browser turns up and gets redirected. But most application-to-application access in an enterprise never involves a browser — a service principal gets a token and presents it to an API, which decides. This page is the API.

Note for Entra ID: an access token issued for Microsoft Graph cannot be validated by anyone but Graph — the signature covers a nonce only Microsoft holds, so verification will fail no matter what you do. Tokens issued for an API you expose on your own app registration validate normally.

Inspect an access token

Paste a token from anywhere — a curl call, a Postman run, a log — and see exactly which check passes and which fails.

The token is never stored. Only the verdict and the individual check results are written to the activity log.

Get a token as the application itself

Runs a client_credentials grant using the connection's client ID and secret. No user is involved — this is the service principal path.

A public client (PKCE, no secret) cannot use this grant — which is itself worth demonstrating.
